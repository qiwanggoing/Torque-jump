# 从论文基线到 sstill6:改了什么、好了多少、为什么

Oct 5, 2026 · @QI

## 一页结论

从论文基线到 `sstill6@19500`,最大的改变不是命中率,而是**撤掉了 PD 脚手架**:基线有 20% 的 PD 常驻(α\_PD = 0.10),`sstill6` 是全相位 α\_PD = 0.000 的纯力矩。命中率的账要看协议：论文协议（全 DR）下 0.87 → 0.65，但在真机口径（标称质量）下是 0.82 → 0.86 反超，且工作区间互补（见「正式结果」）。稳定换来的是：落地站稳 82% → 98%（标称下八档全 100%）、settle 时间 0.57 → 0.39 s、落地漂移 −21%、离地 ω\_y 从 −0.63 到 −0.01 rad/s。代价是近档精度和执行器余量（负载全线更差）。距离 0.845 → 1.001 看着 +18%，但其中九成是助跑，净飞行持平。

基线的 hit / err 更好,但那是在 PD 一直帮忙的前提下。两者不是同一个控制问题。

`sstill6` 的 `dist` 在**每一个**命令上都被助跑虚高了 —— creep 是基线的 1.6–2.0 倍。所以那 +18% 不是能力。但 creep **不进**起跳锚的误差，它只虚高 `dist` 这一个数字；近档 hit 的亏损是另一个原因。**creep 随命令线性增长，不是常数** —— `signed_dy` 的 `BINS` 是按 env 轮询的单命令列表，所以每一档要单独跑一次：

净飞行在远端两边基本持平（0.890 vs 0.872），在近中端 `sstill6` 反而更远 —— 而那里的命令是更短的，所以更远就是**过冲**。还要注意：**在同一个命令上比净飞行或起跳速度近乎是同义反复**。err 是起跳锚的，两边都在跟踪命令，所以净飞行 ≈ 命令 + 跟踪误差，它量的是精度不是能力；能力要看远端的饱和值。基线自己的起跳速度从 2.148 涨到 2.999、仰角从 63° 降到 45°，证明策略确实在按命令调制起跳。

settled 从 82% 到 98% 的机制在起跳那一瞬。基线离地时机身 pitch 是 −5.5°、ω\_y 是 −0.63 rad/s；`sstill6` 是 0.0° 和 −0.01 rad/s。飞行中 ω 守恒、姿态是 ω 的积分，所以基线是**带着往前栖的转速离地、靠落地 PD 把它救回来**，而 `sstill6` 是干净离地、落地时本来就平。这是全文最宝贵的一条：纯力矩不是用更强的落地控制补上 PD，是用**更干净的起跳**绕开了落地控制这个问题。

代价里要多记一条：**站立滚转角是对基线的退化**。roll 摆幅 5.35° → 8.48°，终值 +0.94° → +6.69°，最差 env 20.0°。而站立横向**位移**两边都只有 2 mm。所以看到的“往一边倒”是**倾角**不是平移：`stand_still` 的速度刹车按住了平移，没按住倾角（它罚的是 `base_ang_vel[:, :2]` 的平方，一个**静止的**倾角成本为零）。这是和助跑、非脚触地同一个形状的第四个结构洞。

分档数据说清了 hit 些在哪里：输的全是**近档**。

远档（0.70–1.00）只输 6–9 点，近档（0.30–0.60）输 26–51 点。**原因是起跳仰角偏平，不是助跑。** `sstill6` 在每个命令上都比基线平 2–5°（cmd 0.50 差 4.7°）。拿弹道公式核对 cmd 0.30：

```latex
R = \frac{v^2 \sin 2\theta}{g} = \frac{2.184^2 \sin(124.4^\circ)}{9.81} = 0.401\ \text{m}
```

它的弧长就是 0.401，实测净飞行正好 **0.401** —— 它老老实实飞完了一条偏平的弧，所以短命令必然过冲（err 0.107 vs 基线 0.057）。基线反而落在自己弧长之内（0.345 vs 弧 0.379），近端在**刹**—— 它有落地 PD 可以刹。所以近档是**角度调制**问题，对症的改法在起跳角，不在抑制助跑。

容差扇描说明近档的偏差是**温和的**：把容差放到 0.20 m，`sstill6` 近档恢复到 0.99–1.00，所以不是跑飞而是稳定地过冲 0.10–0.20 m。但在每一个容差、每一个档位上基线都更准，没有例外。

## 够程饱和：cmd 1.00 超出了两边的物理极限

命令从 0.90 加到 1.00（+0.10），净飞行只涨 **+0.029**（基线）和 **+0.016**（`sstill6`），起跳速度只涨 1.2%。所以 cmd 1.00 两边都只在分布的上尾打得到（三跳中一跳，单跳 play 看到 HIT 是正常的）：hit 在 0.90 还有 0.90 / 0.81，到 1.00 塔成 **0.40 / 0.34**。`DX_MAX=1.0` 高过真实够程 ≈ 0.90，这是「课程冲过够程」那个老毛病又一次。把这个不可能的档位剔掉，全范围 hit 是 **0.93（基线）vs 0.69（`sstill6`）**。

那 0.42 m 助跑**买不到一分命中**：起跳锚让目标跟着它一起往前挪，`dist` 到 1.289 ≈ 1.3，目标也在 1.417，还是欠 0.13。

**但 1.00 很近，而且不需要更强的腿。** 45° 跳 1.00 m 需要 3.13 m/s，现在 3.036 —— 差 3%。而且 `sstill6@1.00` 按它自己的 43.0° / 3.036 m/s，弧长该有 0.937，实测净飞行只 0.872，**白丢 0.065**（弹道式按等高起落算，实际落点略低，所以真实缺口更大一点）。两条路：

1. ~~把远端仰角拉回 45°~~ —— **在远端几乎不值钱**。`sin 2θ` 在 45° 附近是平的：同速度下 43.0° → 45° 弧长只从 0.9373 涨到 0.9396，**+0.002**。仰角这条只在**近档**有分量（那里偏平 4.7° 就多飞 0.037）。
2. **找回那 0.065** —— 实测净飞行 0.872 vs 自身弧长 0.937，丢了 7.0%。收腿时机 / 落地姿态。但即使全找回也只到 0.937，还差 0.063。
3. **起跳速度** —— 唯一能单独闭合缺口的量。若那 7% 损耗保留，净飞行 1.00 需 **3.25 m/s（+7.0%）**；若损耗清零，需 **3.13 m/s（+3.2%）**。现在 3.036。而这正好撞在小腿速度墙上（早期 `torque_diag` 测到四膝全冲 110–135% v\_lim、力矩归零）。

所以诚实的结论是：**cmd 1.00 的 hit 0.31 离这个构型的诚实上限不远**，要稳定命中得动起跳速度，而那是硬件墙。**真正摆在桌上的分是近档的 26–51 点**（cmd 0.30–0.60 hit 只有 0.47–0.70），而那里我们手上有一个具体机制（仰角偏平）和一个干净的对照（基线在同命令下 hit 0.93–0.98）。

两条都未验证。

## 纯力矩策略被 PD 脚手架打死：陷阱是双向的

`sstill6@19500` 在 cmd 1.00 上，只改 `LOAD_PD_SCALE`（第二级 fade 乘子），其余全部不动：

|  | α\_PD = 0.000（训练端点） | α\_PD = 0.100（论文基线的 PD 水平） |
| --- | --- | --- |
| hit | 0.31 | **0.00** |
| dist | 1.283 | 0.864 |
| err | 0.145 | **0.387** |
| settled | 95% | 49% |
| creep | 0.417 | 0.248 |
| 净飞行 | **0.866** | 0.616 |
| 起跳 \|v\| | **3.036** | 2.600 |
| 起跳仰角 | 43.0° | **54.9°** |

**给纯力矩策略加回 10% 的 PD，它归零。** 1140 跳 hit = 0.00。机制很清楚：PD 先验是**五关键帧相位调度参考轨迹**，那些关键帧编码的是 PD 时代的起跳形状；把它以 10% 的权重叠在一个已经学会平、快的纯力矩起跳上，把仰角拉回 54.9°（+12°）、把起跳速度抽走 14%，净飞行跌 29%。

所以那三个 eval 陷阱里的第三条要改强：**`LOAD_PD_SCALE` 给错两个方向都致命**。给 PD 版 ckpt 撑得太少会把它看成垃圾，给纯力矩 ckpt 撑得太多同样把它看成垃圾 —— 而后者更难发现，因为不设这个变量就是 1.0（默认值）。

⚙️ **工具缺陷：** `play_landing.py` 的 `replay pd_alpha=` 只算了第一级 fade（`pd_prior_weight × max(floor, 1−gs)`），**没乘第二级的 `_load_pd_scale`**。所以 α\_PD=0.000 和 0.100 两种情况它都打印 `0.100`，分辨不出跑的是哪个。本节这张表是唯一的判别依据：在 α\_PD=0.100 下根本不可能出现 cmd 1.00 的 HIT。未修。

五项改动各自的贡献:

| 改动 | 作用 | 代价 |
| --- | --- | --- |
| `PD_TARGET_OBS` | 让 fade 能走到 0(1012 维版本卡死在 0.040) | 观测 1012 → 1024 |
| `PD_FADE_SCOPE=all` + 闭环 load fade | 全相位纯力矩,guard 防崩 | settled 从 82% 掉到 41% |
| **所有 fade 阶段减半** | hit 持平、err/settled 更好、助跑 −32%、settled 变稳定 | 无 |
| `stand_pose` | 破 0.97 m 够程墙到 1.43 m、settled 41% → 79% | 近端精度、助跑 +70% |
| `stand_still` (W=6) | 起跳前站姿 0.228 → 0.301、settled → 98% | hit 0.81 → 0.65 |

## 起点:论文基线不是纯力矩

论文报告的是 `Sep26_04-41-34_sls15_s1` 的 `model_14700`:基线配置加上 `SUCC_LAND_SIGMA=0.15`(给 `successful_jump` 乘一个落点精度高斯核)和 `SUCCDIST_CAP=1`(`successful_distance` 在命令处封顶)。全范围命中 0.87、误差 0.064、天花板 1.16 m、站稳 83%。

关键的一点:**它的 PD 先验永远不归零**。`pd_fade_floor = 0.2` 让

```latex
\alpha_{PD} = w_{PD}\cdot\max(\text{floor},\, 1-s_{\text{general}}) = 0.5 \times 0.2 = 0.10
```

从 iter 2100 一直留到 14700。那 10% 不是装饰——逐相位反事实测量(eval 时按相位清零 PD)显示:

| PD 关在哪个相位 | 触地次数 | hit | PD 力矩占比 |
| --- | --- | --- | --- |
| 不关 | 1027 | 0.87 | — |
| landing | 1097 | 0.85 | 0.269 |
| stand | 1006 | 0.80 | 0.141 |
| prelanding | 1077 | 0.75 | 0.351 |
| flight | 1368 | 0.56 | 0.448 |
| **load** | **1** | **0.00** | **0.096** |

**脚手架最关键处恰好是它最小处,完全反相关。** load 段策略自己出 90.4% 的力矩,拿掉那 9.6%,触地从 1027 掉到 **1**。原因是**门不是力量**:`require_squat_before_takeoff` 让蹲姿没保持住就根本不起跳,那 9.6% 在满足一个二值前置条件。

由此而来三个问题:

1. **现有调度永远不会过渡到纯力矩**。floor 把那 9.6% 保住,策略从没被要求补上。
2. **全局淡出必然失败**。同时撤掉四个无门的相位和唯一一个有门的;load 一失守起跳归零,其余相位也就没了学习信号。
3. **落地站稳一直是 PD 在做**。这一条是后来量化的,见下节。

## 改动一:让策略看到 PD 拉向哪里

`PD_TARGET_OBS=1` 在观测末尾追加 12 维:

```latex
q^{\text{ref}} = (q_{\text{pd\_target}} - q_{\text{default}}) \cdot s_{\text{dof\_pos}}
```

观测从 1012 维变 1024 维。

**为什么加这个——fade 不稳的病根是策略对脚手架相位盲。**

PD 先验不是一个恒定的"拉回默认姿态"的弹簧,它是按相位调度的**五关键帧参考轨迹**:

| 相位 | PD 目标 |
| --- | --- |
| load(跳跃中·未起跳·未达蹲深) | `q_squat`(蹲姿) |
| 着地 / 蹬伸 | `q_ground` |
| airborne | `q_air`(收腿) |
| prelanding | `q_pre`(半伸) |
| landing | `default_dof_pos`(挢立) |

改动之前策略在观测里只能看到 `pd_prior_alpha` 一个标量——脚手架的**强度**。它感受到一个外力,却**不知道这个力指向哪个姿态**。这导致两件事:

1. **它无法学习"接手"。** fade 要求策略逐步补上脚手架让出的那部分力矩。但要补一个力,得先知道它在把关节往哪里拉。相位盲的策略只能事后对残差做反应,而不能预测性地接管。
2. **load 段最严重。** 那一段的关键帧是蹲姿,而蹲姿是起跳门的前置条件(下节)。策略必须自己生成蹲姿,却从没被告知蹲姿长什么样——等到支撑消失的那一刻才开始重新发现。

所以这 12 维把问题从"替掉一个你归因不了的力"改成"跟踪一个你看得见的参考"。参考引导的跳跃文献(Li 2023)的策略正是把参考轨迹进观测的——它还额外给了 t+1 / t+4 / t+7 的预览帧;我们只给了当前帧 t,没做预览。

**对照数据。** 同种子、同 schedule、同 guard,唯一差别是这 12 维:

|  | 观测 | load fade 结果 | eval hit | span |
| --- | --- | --- | --- | --- |
| `allfade2_s1` | 1012 | **暂停 25 次,卡死在 α 0.040** | 0.16 | −0.023 |
| `allfade2_pdtgt_s1` | **1024** | **fade 到 0.000** | 0.72 | +0.505 |

1012 维版本的 guard 反复触发(命中率掉到阈值以下就暂停),永远走不完;1024 维版本一次暂停都没有。`span` 是 `dist@1.00 − dist@0.30`,它的 −0.023 意思是命令完全失效——不管令你跳多远都跳同样远。

镇像图也跟着改了:`sym_loss` 的左右镜像排列需要知道 extras 的维度(32 → 44),这 12 维按 `dof_pos` 的奇偶性镜像。

## 改动二:全相位纯力矩 + 闭环守卫

**为什么要按相位分开撤、而不是直接把 α\_PD 降到 0。**

上节那张逐相位反事实表里有一个完全反相关:**脚手架力矩占比最低的相位(load, 9.6%),恰好是拿掉它就全滞的那一个**(触地 1027 → 1)。而占比最高的 flight(44.8%)拿掉只是连续退化(hit 0.87 → 0.56)。

区别在于**门不是力量**。`require_squat_before_takeoff` 是二值前置条件:蹲姿没保持住就根本不起跳。load 段那 9.6% 不是在"帮忙发力",是在**满足一个开关**。所以它是崖,其余四个相位是缓坡。

这解释了为什么之前的全局淡出必然失败:它**同时撤掉四个无门的相位和唯一一个有门的**。load 一失守起跳归零,其余相位连学习信号都没了——六个历史 run 在 `pd_prior→0` 处坑的形状一致,看起来像六种不同的失败,其实是同一个。

所以路线改成**按崖/缓坡排序**:全局 fade 只负责把 α\_PD 降到地板 0.10(保住发现期的稳定)→ 再单独、闭环地撤 load 段 → 最后其余四相。`PD_FADE_SCOPE` 就是这个开关:

- `scope=load` —— 只罩住 load 段,其余四个相位**永远停在 0.10**,永远到不了纯力矩
- `scope=all` —— 乘子作用于所有相位,α\_PD 才能真正归 0

而 **闭环(guard)是因为 load 段是崖**。开环定速撤一个崖式依赖没有退路;闭环的意义是**卡住的值本身就是结果**——它直接回答"纯力矩下策略能自产多少蹲姿"。事实上 1012 维版本就卡在 0.040 没再动,那就是它的答案;加了 PD 目标观测之后才走到 0。

两级串联。第一级是开环的全局 fade(`general_scale` 把 α\_PD 从 0.5 降到地板 0.10);第二级是新加的闭环 `_load_pd_scale`,再乘上去把它推到 0。`PD_FADE_SCOPE=all` 让这个乘子作用于**所有相位**——若为 `load` 则只罩住 load 段,其余四个相位会停在 0.10。

```latex
\alpha_{PD}^{\text{eff}} = 0.5 \cdot \max(0.2,\, 1-s_{\text{general}}) \cdot \text{load\_pd\_scale}
```

端点 = 0.5 × 0.2 × 0.0 = **0.000**。

**guard 怎么工作。** 每隔 `LOAD_FADE_HOLD` 环境步把 `load_pd_scale` 减 0.1(10 档 1.0→0.0)。每次推进前比较命中率的 EMA:若 `hit_ema < 0.6 × hit_ref`(`hit_ref` 在第一次推进时 latch)则**暂停并重置计时器**,不推进。这就是上节第 2 条的解药:不再同时撤所有相位,而是一档一档试探,撑不住就停。

实现过程中有两个 bug 让 guard 形同虚设,都修了:调用顺序错(在 `landing_hit_rate` 写入之前就读它,`extras` 每次 reset 被清空 → `hit_ema` 永远为 0),以及 EMA 累积被关在门后面(`ref` latch 成 0.013 而不是 \~0.20)。

**最重要的发现:落地站稳一直是 PD 在做。** 在同一个 run 内按 checkpoint 测出的剂量曲线,命中率和误差全程按住不动:

| iter | α\_PD | hit | err | **settled** |
| --- | --- | --- | --- | --- |
| 6000 | 0.080 | 0.23 | 0.204 | **64%** |
| 8000 | 0.040 | 0.22 | 0.203 | **33%** |
| 10000 | 0.000 | 0.24 | 0.193 | **16%** |
| 12000 | 0.000 | 0.35 | 0.148 | **0%** |

命中率和误差基本不变,只有 PD 在退、只有 settled 单调崩塌。这比跳 run 对比强得多——论文基线的 83% 和纯力矩的 41% 这个差距,**不是哪一刀的问题,是纯力矩的固有代价**。后面两项改动就是为了把这 40 多个百分点赚回来。

## 改动三:所有 fade 阶段减半

三个数字的改动,其余配置逐字不动:

|  | 原值 | 新值 | 效果 |
| --- | --- | --- | --- |
| `GROWTH_WARMUP` | 192000 | 96000 | 满 PD 到 iter 2000 → 1000 |
| `GROWTH_X0` | 384000 | 192000 | α\_PD 到地板 @ iter 5000 → 2500 |
| `LOAD_FADE_HOLD` | 24000 | 12000 | α\_PD → 0 @ iter 9500 → **4750** |

纯力矩训练预算从 10500 iter 涨到 **15250**。

**为什么敢这么改。** 原 20000-iter run 的 fade 全程没被压力测试过:10 档每档间隔精确 24000 步无缺口、`PAUSED` 零次、而且 `hit_ema` 全程是**上升**的(0.198 → 0.263),跳闸阈值 0.6×ref ≈ 0.119 从未接近。`HOLD=24000` 是为 1012 维版本调的(那版同样 HOLD 下暂停 25 次卡死),加了 PD 目标观测之后难度变了,HOLD 没跟着改。

**结果。** 快 fade 的最佳点 vs 慢 fade 的最佳点:

|  | 慢 fade `25k@22200` | 快 fade `fadehalf@18000` |
| --- | --- | --- |
| hit | 0.81 | **0.81** 持平 |
| err | 0.079 | **0.073** |
| settled | 77% | **92%** |
| dist | 0.908 | 0.778 |
| `run_up_creep` | 0.348 | **0.236** (−32%) |

距离那 14% 的差**几乎全是助跑**:减掉 creep 后真飞行 0.560 vs 0.542,差 3%。慢 fade 的"距离优势"是蹭出来的。

**最强的一条是 settled 的稳定性。** 快 fade 扇 17 个 checkpoint,16 个在 83-98%(均值 \~93%);慢 fade 扇 12 个是 34/40/50/58/69/77/79/81/83/90% 混乱震荡。之前那个 90% 是 12 点里挑出的孤点(怀疑有选择偏差),快 fade 的 95% 是常态。

机制:纯力矩时间 10500 → 15250,策略有更长时间**真正学会无 PD 落地控制**,而不是在 PD 撤除后一直摇摆。助跑那一条也支持这个解释:慢 fade 的 creep 在训练中持续长(0.189→0.266→0.311→0.348),快 fade 稳在 0.20 不涨——**PD 替策略撑着站姿和下蹲时,策略自己的动作输出就空出来了,可以拿去往前蹭;PD 一撤,那些动作必须用来蹬地**。

## 改动四:stand\_pose

起跳前站立段的**正奖励**。

```latex
r_{\text{stand\_pose}} = \mathbb{1}[\neg\text{jumping}] \cdot \exp\!\left(-\frac{\lVert q-q_{\text{default}}\rVert_1}{\sigma}\right) \cdot \exp\!\left(-g\,\lvert z-z^{*}\rvert\right)
```

三个设计决定:

**① 用正奖励而不是惩罚。** 那一段原本靠 `default_pos` 这堵 L1 墙撑着(测到 −0.807,是最大负项)。惩罚是"偏了就挨打",策略会买最便宜的止痛药——而那通常不是你要的姿态。改成"摆对了就给钱"。

**② 姿态 × 高度相乘,不奖单个标量。** 只奖 `base_z` 是退化的:前趴和劈叉都能把它压低(历史上被这两种姿态刷过两次)。要求同时满足默认关节姿态,基本只剩一种解。

**③ 卡死在 discovery 之后。** 给站立付钱是这个任务的已知杀手——`stand_no_takeoff` 被删、`first_jump_delay 55→200` 被撒,原因都是"站着太舆服就不跳了"。所以 `_takeoff_omega_on`(succ EMA ≥ 0.80)没 latch 之前它**一分不给**。

**结果。** 破了卡很久的 0.97 m 够程墙:

|  | 基线 `allfade2_pdtgt@20000` | `standpose@19900` |
| --- | --- | --- |
| cmd 0.90 / 1.00 的 dist | 0.974 / 0.974 (饱和) | 1.377 / **1.433** |
| cmd 1.00 的 hit | **0.00** | 0.40 |
| settled | 41% | **79%** |
| span | +0.476 | **+0.814** |

基线在 cmd 0.90 和 1.00 上 dist 一模一样 0.974——硬墙;`standpose` 没有这个平台。

**但它起作用的机制跟设计意图不同。** 当初的逻辑是"摆正姿态 → 减轻 `default_pos` 那堵墙"。早期确实对上(iter 1650:−0.368 vs 基线 −0.419),但**到纯力矩段 `default_pos` 已经跟基线持平**。姿态惩罚那条因果链断了,收益却留下来了,而且落在一个没预期的地方——远端够程。比较可能的解释:给起跳前站立付钱让**起跳初始姿态变得一致可重复**,而远端是余量最薄的地方,起跳一致性在那里的边际价值最高。这是假设,没做消融。

代价:近端精度退化(cmd 0.30 的 hit 0.55 vs 基线 0.85)、助跑 `run_up_creep` 0.348 vs 0.205(+70%)。

## 改动五:stand\_still

把落地那套速度刹车搬到站立段——就是 `landing_stability` 换个门:

```latex
r_{\text{stand\_still}} = \mathbb{1}[\neg\text{jumping}] \cdot \exp\!\left(-\frac{\lVert v\rVert^2}{\sigma_{\text{lin}}}\right) \cdot \exp\!\left(-\frac{\lVert \omega_{xy}\rVert^2}{\sigma_{\text{ang}}}\right)
```

**为什么需要它。** `meas_prejump` 测到 `fadehalf@18000` 起跳前机身**单调下沉**:0.331 → 0.291 → 0.274 → 0.252 → 0.228 m(395 步时 0.213),而 `stand_pose` 全程在发分。**位置/姿态型目标分不出"蹲在低位"和"正在往下掉"**——两者收到同样的 `exp(−|z−z*|)`。落地段没这个毛病,结构差别就是 `landing_stability` 付钱给**低速度**。

**σ 必须比落地那套紧 \~60 倍。** 落地用 lin 2.0 / ang 1.0,是因为真实落地 |v| ≈ 1.3;安静的站姿 |v| 只有 0.1-0.3,用那个 σ 会得到 `exp(−0.09/2.0) = 0.96`——贴死在 1、零梁度。这正是 `LAND_STAB_W=5.0` 失败的原因(下节)。用 lin 0.03 时 0.2 m/s 的下沉给 `exp(−1.33) = 0.26`,在站姿真实存在的速度区间里有梁度。

**剂量响应——高权重反而不治。**

|  | W=0 基线 | W=2 | W=6 |
| --- | --- | --- | --- |
| hit (端点最佳) | 0.81 | 0.54 | 0.67 |
| settled | 92% | 99-100% → **后期崩到 5-15%** | 87-98% 稳定 |
| 起跳前站姿 | 0.228 沉 | 0.318 锁死(@14000) | 0.301 近稳(@19500) |
| `rew_stand_pose` | 0.097 | 0.121 | **0.062** |

最后一行是机制:**权重太高时 `stand_still` 把 `stand_pose` 挤掉了**。关键在于**缓慢下沉的速度是很低的**——一个缓慢下蹲几乎完美满足"别动",却完全放弃"挢立的高度"。W=6 时策略找到了那个更便宜的解:蹲着不动。

最终采用 **W=6**——W=2 虽然站姿最好(0.318 + settled 100%),但它在 iter 19000-20000 段 settled 崩到 5-15%、hit 封顶 0.54。

## 失败的尝试

三次失败都有具体机制,不是"效果不好"。

**① `landing_stability` 加权(1.0 → 5.0)——饱和。**

它本来是为了把 settled 从 41% 拉回 82%。实测 41% → **44%**(+3 点),同时远端 `farband_hit_smooth` 从 0.214 掉到 0.038(**−82%**)。

机制:权重给了 5 倍,底层那个量只动了 **13%**(0.0484 vs 0.043)。config 自己的注释记着 σ 从 0.25(`exp(−大)≈0` 没梁度)放宽到 2.0——**放过头了,从"恒为 0"翻到"恒为 1"**,两头都没梁度。所以调权重不可能有用。另一条印证:该项在训练中是**往下走**的(0.275 → 0.242)——策略越会跳远落地越不"稳",两者在当前奖励形式下直接对立。

**② `stand_still` W=2——后期崩。**

中段(ckpt 12000-15000)settled 99-100%、起跳前站姿锁在 0.318(项目最高),看起来是赢家。但 19000-20000 段 settled 崩到 **5-15%**,hit 封顶 0.54。这个判错是下节那条教训的直接后果。

**③ 提高 `sym_coef`(1.0 → 3.0 / 10.0)——三个代价。**

动机是治横向偏置(`fadehalf@18000` 在 767 跳里 **100% 向左**、平均 +0.1325 m、sd 仅 0.0236)。结果:

| `sym_coef` | 等变误差 | 横向偏置 | settled | `rew_collision` |
| --- | --- | --- | --- | --- |
| 1.0 | 0.002-0.003 | 0.045 | 98% | −0.053 稳定 |
| 3.0 | 0.0014 | **0.091**(更大) | 89% | −0.060 \~ **−0.261** |
| 10.0 | 0.0005 | 0.004 对称 ✓ | **1-22%** ❌ | −0.050 \~ −0.164 |

三条结论:

1. **等变误差降低不等于横向偏置减小。** coef=3 的等变误差比基线低,偏置反而更大。
2. **能去掉偏置的系数强度已超过任务能承受的范围。** 只有 coef=10 真正压住偏置,而那个强度下 sym 项 = surrogate 的 1.5 倍,settled 直接崩。这把"等变损失只去偏置、不提供回正力"量化了。
3. **多了一个没预料到的代价:非足部触地出现 2-5 倍异常点。** 两条基线(coef 1.0)的 `rew_collision` 都稳在 −0.053 到 −0.056,两条提高系数的 run 都出现暂涌点。`sym3@17000` 的 −0.261 是基线的 **4.9 倍**——换算下来每 episode 约 52 个触地步 ≈ 260 ms 的后腿关节坐地。

所以 `sym_coef` 这条线整体被毙。唯一的副产品是 `sym3@20000` 的任务指标好看(hit 0.79 / err 0.080),但它仍有 0.069 的一致右偏和 1.7 倍的 collision。

## 方法论:为什么必须扇 checkpoint

**同一个 run 内相邻 checkpoint 的方差大得让少数点没有判别力。** `standpose_25k_s1` 扇 12 个点:

| ckpt | hit | settled |
| --- | --- | --- |
| 21500 | **0.43** | 79% |
| 22000 | 0.76 | **90%** |
| 22200 | **0.81** | 77% |
| 23500 | 0.61 | 34% |
| 24000 | 0.38 | 58% |
| 25000 | 0.49 | 83% |

hit 跳度 0.43↔0.81、settled 跳度 **5%↔100%**,间隔只有 500-1000 iter,无趋势。每次 eval 是 512 env × 1700 步 ≈ 1100 跳,样本够——**不是采样噪声,是 PPO 晚期策略本身在 churn**。

实操铁律:这类 run 跑完**必须扇 10+ 个点**。若只测最终几个,`25k` 会得出"维训把策略搞坏了"(23500 的 settled 34%),直接漏掉 `22000`(settled 90%)和 `22200`(hit 0.81)。

**我在本轮因此连续判错三次。** 全部源于拿训练中段的点外推:

1. 中段(12000-15600)→ "`stand_still` W=2 治住了、W=6 三项全输"
2. 看到 `sstill6@16000`(hit 0.65)→ "W=6 追上来了"
3. 完整扇描 → **W=6 才是更好的那个**

类似地,对快 fade 的远端指标我用局部趋势判错两次(在 7700 说"领先 2 倍"、在 10600 说"卡住走平"),最终 18000 到 hit 0.81。

**eval 协议的三个陷阱。** 每个都会让好策略看起来是坏的:

| 陷阱 | 不给的后果 |
| --- | --- |
| `STANCE_CURR=0` 必须显式给(默认 1) | 同一 policy 差 **6.5 倍**(hit 0.09 vs 0.59),而且会把 yaw 病症整个藏起来 |
| `PLAY_LANDING_ADDED_MASS=0.1`(精确标称质量是**死区**) | hit **0.00** vs 1.00;`play_landing.py` 的默认值 0.0 正好在死区里 |
| `LOAD_PD_SCALE` 必须匹配该 ckpt 的训练端点 | 纯力矩策略被满 PD 压垮,出假象 |

第三条还有个子问题:中期 ckpt 的 `load_pd_scale` 要从日志的 `curriculum_load_pd_scale` **读实际值**,不要用公式推——我推算错过 0.2。

## 未解决的问题

三个问题,**前两个是同一种结构空洞**——某个行为对奖励来说是免费的。

**① 横向偏置。** 落点目标的 y 也按起跳锚给:

```latex
\text{landing\_target}_y = y_{\text{takeoff}} + \text{cmd}_y
```

所以**起跳前的横向位移跟前向助跑一样被锚完全吸收掉,奖励看不见它**。`err` 只度量飞行段的偏差。各 run 的偏置幅度和**方向都是训练中随机获得的**:

| run / ckpt | load+push 横向 | 方向 |
| --- | --- | --- |
| `fadehalf@18000` | 0.1325 m | 100% 左 |
| `sym3@19500` | 0.0914 m | 100% 右 |
| `sstill6@20000` | 0.0451 m | 100% 右 |
| `sstill6@19500` | 0.0274 m | 随机(52%) |
| `sym10@19500` | 0.0040 m | 随机(42%) |

`sym_coef` 已证伪(上节)。对症的应该是**在 load/push 段加横向惩罚**——直接给横向加回正力,而不是约束策略的对称性。未做。

**② 后腿非足部触地。** 用户 play 时观察到后腿关节坐在地上,数据确认了(`sym3@17000` 的 `rew_collision` = −0.261 = 基线的 4.9 倍)。机制:

- `penalize_contacts_on = ["thigh", "calf", "hip", "base"]` —— 有惩罚,但权重只有 −1.0,占总收益不到 **0.3%**
- `terminate_after_contacts_on = []` —— **landing 任务把父类的 `["base"]` 覆盖成空列表**,所以什么都不终止。`check_termination` 里的 `collision_cutoff` 对空集求和恒为 0

还没分清**落地坐地 vs 蹬伸坐地**——两者修法相反(前者加落地约束,后者得让后腿在蹬伸时真的出力;而"后腿在 push 段是最大空料"是个长期问题)。直接加 `collision` 权重有"治症不治因"的风险。

**③ sim2sim 不迁移。** `standpose@19900` 移到 MuJoCo:**24 次跳跃零命中**,而且命令跟踪彻底失效(cmd 0.3 跳 0.704 m 超 2.3 倍、cmd 0.9 只跳 0.088 m)。上一代带 PD 的 `model_4600` 移植后只差高度 3.7% / 距离 9%。

移植过程中找到的主因:MJCF 有 Isaac 完全没有的关节阻尼 0.050 / armature 0.005 / 摩擦损耗 0.050。纯力矩蹬伸本来就在膝速度墙边缘,这点额外耗散足以压死它;而 `α_PD=0.100` 时 PD 顶着,把问题掩盖了整整一轮对拍。修正后能跳(起跳 vz +2.19、飞行 0.795 m),但跳跃质量仍不达标。

还有一个认识要更正:上一次 port 那个"action diff 1.9e-6 对拍成功"**只覆盖观测管线和网络输出**——action 是网络的输出,根本不经过力矩律,所以那次验证从未验证过执行器模型。

**基线的 settling 随命令单调退化（0.97 → 0.69），`sstill6` 全档位平坑在 0.95–1.00。** 论文把这个退化当作「strict settling 的核心结果」，并由此提出两个前沿：**稳定落地前沿在 0.80–0.90**、距离跟踪前沿在 0.90–1.00。现在：

- 落地漂移两边都随命令长三倍，但 `sstill6` 起点和终点都更低（@0.90 漂 0.167 vs 0.221，−**24%**）。

- **基线**：跟踪好（近档 0.93–0.99）、命令越远越站不稳 → 瓶颈在**落地**。
- **`sstill6`**：全档位都站得稳、但近档跟不准（0.47–0.70） → 瓶颈在**跟踪**。

这也解释了为何汇总 settled 是 82% vs 98%：基线的 18% 损失集中在 0.60–1.00 六个档位。

## ⚠️ 换成真机口径，结论翻转

上面所有数字用的是**论文协议 = 全 DR**：`meas_land.py` / `meas_var.py` / `meas_complete.py` **一个 DR 字段都不碰**，所以走配置默认——质量 `[−1, +1] kg` 随机、摩擦 `[0.5, 1.25]` 随机。而 `play_landing.py:123-131` 显式关掉它们（`randomize_friction=False`、`push_robots=False`、`added_mass_range=[ADDED_MASS, ADDED_MASS]` 固定值）。**真机就是 URDF 标称，所以这两个口径里后者才是「能不能上机」的那个。**

| cmd | 基线 全DR | **基线 标称** | `sstill6` 全DR | **`sstill6` 标称** |

那个「0.87 vs 0.65」在真机口径下是「**0.82 vs 0.86**」。分工干净得出奇：**基线独占 0.30–0.80（六档全是 1.00），`sstill6` 独占 0.90–1.00（0.98 / 0.66 对 0.53 / 0.00）。**

### 基线有标称质量死区，`sstill6` 没有

基线在标称下 cmd 0.90 只剩 0.53、cmd 1.00 是 **0.00**，但容差扇描是 `0.04 / 0.53 / 0.93 / 1.00 / 1.00` 和 `0.00 / 0.00 / 0.00 / 0.12 / 0.99` —— **稳定欠程约 0.10 和 0.16 m，不是翻车**。它在标称下每一档的 `dist` 都更短（1.158 → 1.098），这是 mass-blind 策略把一次蹬伸调给质量分布主体的指纹。换句话说：**它在全 DR 下那个 0.40 是靠抽到偏重的那部分 env 撑起来的。**

`sstill6` 方向相反：标称下 `dist` 变**长**（1.289 → 1.344），说明够程不靠有利抽签；err@0.90 = **0.031**，是这整轮里最准的一个数。

`sstill6` 在标称下**八个档位全部 100%**，settle 时间 0.32–0.43 s 平坦。基线 ALL 95% 但从 1.00 退化到 0.86、时间从 0.40 爬到 0.63 s。前面那个「稳定落地前沿消失」的结论在两个口径下都成立。

### 铁律

**报任何 hit 必须写明 DR 条件。** 全 DR = 论文 Tab 6.1 协议（重测逐项复现）；标称 = 真机口径。两者都不「错」，但不可混用 —— 差距可达 **0.00 ↔ 0.71**。本文前面所有未标注的数字均为全 DR。
